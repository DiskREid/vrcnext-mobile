# Приглашения, создание инстансов, присутствие и изображения0.2.3

## Приглашения из информации о мире

В карточке мира добавлены явные действия «Пригласить себя» и «Пригласить друзей».
Они открывают выбор настоящего инстанса мира, включая раскрытые места друзей и
инстанс, только что созданный с этого телефона. Собственный location пользователя
может быть offline: он не используется вместо выбранной цели. Друзей можно искать,
отмечать нескольких, видеть успешные отправки и ошибки отдельно. Запросы идут
последовательно с паузой;401/429 останавливают оставшуюся очередь. Успешные адресаты
исключаются из повтора. Закрытие окна отменяет ещё не начавшиеся отправки.

## Создание группового инстанса

Новая форма использует фактический grp_ID и актуальный ответ группы с ролями и
myMember.permissions. Явное отсутствие прав отключает соответствующий тип;
неполные сведения не заменяются вымышленными разрешениями, окончательное решение
принимает VRChat. Для members доступны roleIds; поддержаны название и очередь.

Ограничение производительности аватаров передаётся реальным полем
minimumAvatarPerformance, как в исходном VRCNext: Poor, Medium или Good. Отсутствие
ограничения означает отсутствие поля. Ответ создания или дополнительное чтение
инстанса должны подтвердить выбранное значение до автоматического инвайта.
Если сервер его не подтверждает, инстанс остаётся созданным, показывается ошибка,
инвайт не отправляется автоматически; есть повторная проверка.

Адрес берётся из location либо наиболее полного согласованного instanceId/id,
с сохранением group/region/nonce и буквального двоеточия маршрута. Сразу после
успешного POST сохраняется факт создания; неудачная отправка инвайта не возвращает
кнопку, которая незаметно создаст ещё один инстанс. Повторяетcя только инвайт.
Созданный адрес доступен в списке мира до появления в очередном ответе API.
Ошибка обновления сведений мира сохраняет уже открытое окно и результат создания.

## Индикаторы присутствия

Раньше цвет определялся только пользовательским status, который может оставаться
active/ask me/busy даже офлайн. Дополнительно классы status-ask me/status-join me
разбивались пробелом на две части. Теперь отдельная модель использует state и
раскрытое location: офлайн серый, сайт/компаньон полый кружок, игра — точка цвета
выбранного статуса. Неизвестное присутствие не выдаётся за подтверждённый онлайн.
Изменения друзей после открытия профиля обновляют его присутствие без затирания
прочих свежих полей профиля старым списком друзей.

## Исчезающие аватарки

Старый обработчик ошибки ставил img.style.display=none; после этого наблюдатель
видимости не мог вернуть изображение. При уходе за экран также удалялись байты
миниатюры. Теперь ошибка не удаляет геометрию картинки, успешная загрузка возвращает
её, известное резервное фото используется при сбое главного URL. Для видимого
изображения разрешён один ограниченный повтор, без бесконечного опроса.

Нативные превью аватарок уменьшаются до256px, большие фотографии сохраняют прежний
предел1024px. JS-кеш ограничен числом/размером; незавершённые загрузки дедуплицируются
отдельно от LRU, одновременно выполняются не более двух. Загруженные аватарные
миниатюры сохраняются при прокрутке; скрытые разделы не начинают новые загрузки.
После выхода очищается кеш, старые ответы не восстанавливают байты прежней сессии.

Старые API-адреса изображений vrchat.com/api/1 и api.vrchat.com/api/1 приводятся
к фиксированному api.vrchat.cloud после проверки пути: cookie не уходят на
произвольный host. Для application/octet-stream нужен настоящий raster signature
и успешная ограниченная проверка BitmapFactory. JSON/HTML/SVG не принимаются за
аватарку. Белый список внешних хостов не расширен.

## Проверка и ограничения

Проверены контрактные запросы, ошибки/частичный успех, неразмножение созданий,
проверка серверного ограничения, смена присутствия в открытом профиле, восстановление
после ошибки изображения, fallback, прокрутка и новый URL. Браузерный тест использует
изолированную имитацию нативного моста; она не входит в APK и не отправляет настоящие
приглашения. Нативные URL/MIME-проверки выполняются JUnit. Фактические операции
живого аккаунта и изображения на физическом Tecno остаются приёмочными сценариями.
