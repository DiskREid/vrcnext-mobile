# Проверка VRCNext Mobile на Android

Этот план описывает проверки, **ещё не выполненные с настоящим аккаунтом и
физическим Android-устройством**. Наличие APK, успешная компиляция, unit-тесты
транспорта и браузерные проверки деморежима не подтверждают эти сценарии.
Отмечать сценарий пройденным можно после наблюдения ожидаемого результата;
отсутствие нужного аккаунта, права или приложения означает «не проверено».

## Среда проверки

- Собранный APK, Android 8/API 26 или новее и Android System WebView109+.
  Минимальная и целевая версии заданы в `android/variables.gradle` (26 и 35).
- Хотя бы один небольшой телефон, один большой экран/планшет; портретная и
  альбомная ориентация. Для проверки последствий действий — VRChat Web или
  установленный VRChat с тем же тестовым аккаунтом.
- Тестовый VRChat-аккаунт с TOTP либо Email OTP. Оба варианта проверяются
  отдельными аккаунтами/настройками. Для изменений социальных связей — второй
  тестовый аккаунт/согласованный тестовый контакт, не случайные пользователи.
- Для групповых публикаций и инстансов — отдельная тестовая группа и нужные
  разрешения. Для VRC+ возможностей — аккаунт с подпиской и отдельная проверка
  без подписки.
- Для OSC — ПК с VRChat, включённым OSC и известным частным IPv4/UDP-портом в той
  же Wi-Fi сети. Companion не требуется для ручного OSC и в приложении отсутствует.

Стандартный путь Gradle debug-сборки:
`android/app/build/outputs/apk/debug/app-debug.apk`. Установка с подключённого
компьютера после сборки:

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.diskreid.vrcnextmobile/.MainActivity
```

Не записывать пароли, коды 2FA, session cookie, Authorization или полный WebSocket
URL в отчёт. Для ошибки достаточно сценария, времени, версии APK/Android, HTTP
статуса и текста безопасного сообщения. Снимки экрана защищённых окон намеренно
запрещены через `FLAG_SECURE`; этот план не требует отключать защиту.

## Вход, сессия и ошибки

| ID | Действия | Ожидаемый результат |
| --- | --- | --- |
| AUTH-01 | Первый запуск после установки, затем деморежим | Появляется форма входа; деморежим явно помечен. Действия изменения аккаунта заблокированы, реальный вход не выполняется. |
| AUTH-02 | Ввести неверный пароль тестового аккаунта | Понятная ошибка входа, сессия не считается авторизованной; поле пароля не сохраняется между запусками. |
| AUTH-03 | Верный вход с TOTP: сначала неверный, затем правильный код | Появляется второй этап, неверный код отклоняется, правильный открывает действительный профиль. Ошибка не подменяется демоданными. |
| AUTH-04 | Отдельный вход с Email OTP | Правильный endpoint emailotp, письмо/код обрабатываются штатно, профиль загружается. Не считать TOTP-проверку доказательством Email OTP. |
| AUTH-05 | На втором этапе выбрать «Другой аккаунт», затем повторить вход | Частичная сессия очищена; предыдущая 2FA не авторизует другой аккаунт. Это новый вход, а не поддержка нескольких сохранённых аккаунтов. |
| AUTH-06 | После успешного входа закрыть приложение, принудительно остановить и открыть снова | Восстанавливается тот же аккаунт через `/auth/user`, без запроса пароля. При истёкшей сессии появляется вход, не чужие данные. |
| AUTH-07 | Из настроек выйти онлайн; повторно запустить | Cookie удалены, сессия не восстанавливается, журнал мобильной сессии очищен. Затем повторить выход при отключённой сети: локальное удаление обязательно. |
| NET-01 | Войти, открыть список, выключить сеть, обновить, включить сеть и повторить | Баннер offline, явная ошибка запроса; старые данные не выдаются за новый успешный ответ. После восстановления данные загружаются. |
| NET-02 | Свернуть приложение и вернуть; изменить статус тестового друга из другого клиента | WebSocket переподключается в активном приложении; обновление/событие отображается. Работа в фоне не обещается и отдельно не считается пройденной. |
| NET-03 | Проверить 401/403/429 через контролируемый тестовый транспорт, не вызывая лимит спамом | 401 требует входа, 403 не выдаёт успешное действие, 429 показывает ожидание и не повторяет изменение автоматически. Эти ошибки не превращаются в пустой успешный список. |

## Отображение и адаптация

| ID | Действия | Ожидаемый результат |
| --- | --- | --- |
| UI-01 | Все вкладки на узком телефоне в портрете и в альбоме | Навигация, карточки и диалоги доступны; нет обрезанных кнопок или горизонтального прокручивания всей страницы. Навигационная панель учитывает нижнюю системную область. |
| UI-02 | Открыть профиль/мир/загрузку фото, повернуть устройство | Контент остаётся доступным, незавершённое изменение не отправляется само. Диалог можно закрыть; нет пустого WebView. |
| UI-03 | Открыть экранную клавиатуру в Messenger, профиле, поиске и 2FA; повернуть телефон | Поле, ошибка и кнопка отправки доступны прокруткой; клавиатура не закрывает единственный способ продолжить/отменить. |
| UI-04 | Крупный системный шрифт, длинное имя/описание, отсутствие изображения | Текст переносится; есть читаемые подписи и заглушки, основные действия доступны. |
| UI-05 | Быстро сменить поиск/фильтр/вкладку во время загрузки | Поздний ответ предыдущего запроса не подменяет новую выборку. Проверить возврат и системную кнопку Back отдельно: браузерная навигация не доказывает Android Back. |
| UI-06 | Изменить акцент, перезапустить | Цвет сохранён; статусы и ошибки остаются различимыми. Редактор тем и выбор языка не ожидаются в 0.1.0. |

## Чтение данных аккаунта

| ID | Действия | Ожидаемый результат |
| --- | --- | --- |
| READ-01 | Друзья онлайн/офлайн, поиск по друзьям и глобальный поиск | Категории соответствуют аккаунту, private-location не раскрывается. Для аккаунта с большим списком проверить страницы сверх первой сотни и отсутствие дубликатов. |
| READ-02 | Открыть профиль, группы, общих друзей, ссылки | Правильные rank/status/bio, группы и заметка. Приватность mutuals не трактуется как сетевой успех с полной информацией. Неподдерживаемая ссылка получает ошибку. |
| READ-03 | Миры: популярные, активные, поиск имени и ID, свои, избранные, «Загрузить ещё» | Карточки реального API, правильные страницы; карточка мира показывает автора, платформы и доступные инстансы. Пустой ответ отличается от ошибки. |
| READ-04 | Группы: свои/поиск, правила, публикации, галерея, инстансы | Права и приватность учитываются; галереи/публикации грузят дополнительные страницы. Недоступная вкладка не изображает чужие закрытые данные. |
| READ-05 | Аватары: свои, избранные, поиск по ID, публичный поиск avtrdb | Правильные изображения/платформы; публичный поиск передаёт только запрос и не использует VRChat cookie. Не считать аватар Android-совместимым, если API не сообщил такую платформу. |
| READ-06 | Календарь: предыдущий/следующий месяц, весь месяц/день, подписки, многостраничный ответ | Даты показываются в часовом поясе устройства; событие через полночь находится в верном дне. Featured в 0.1.0 отсутствует. |
| READ-07 | Инвентарь: фото, иконки, emoji/static+animated, sticker, prints, items | Правильные категории и изображения, страницы не дублируются. Проверить предмет с templateId без встроенной картинки; отсутствие картинки не должно ломать страницу. |
| READ-08 | Уведомления V1 и V2, повторное обновление, большая история | Дедупликация, правильные sender/message/details, доступ к следующей странице. Если V2 отсутствует, V1 продолжает работать; 401/403 не маскируются под отсутствие V2. |

## Изменения аккаунта

Выполнять на тестовых данных. После каждого шага проверить результат **в другом
клиенте VRChat или после повторной загрузки**, а не только по toast приложения.
Восстановить исходные значения там, где операция обратима.

| ID | Действия | Ожидаемый результат |
| --- | --- | --- |
| WRITE-01 | Изменить статус, текст, bio, местоимения, языки и одну ссылку | Изменены именно указанные поля; после повторного входа значения совпадают. Проверить удаление текста и допустимые длины. |
| WRITE-02 | Прочитать существующую заметку, сохранить без изменения, изменить и очистить | Сохранение без редактирования не стирает заметку; изменённый/пустой текст возвращается сервером корректно. |
| WRITE-03 | Добавить тестовый контакт, принять заявку на втором аккаунте, удалить через подтверждение | Реальные отношения изменены один раз; отмена подтверждения ничего не меняет. |
| WRITE-04 | Block/mute тестового контакта и снять из отдельного списка | Правильный targetUserId, список обновляется; block и mute не перепутаны. |
| WRITE-05 | Добавить друга, мир и аватар в выбранную группу избранного; переименовать группу | Правильная группа на сервере, а не локальное сердечко. Полный перенос между группами/удаление через UI в 0.1.0 не ожидаются. |
| WRITE-06 | Создать Public/Friends+/Friends/Invite/Invite+ инстанс и отправить инвайт себе | Реальные тип, владелец, регион и canRequestInvite соответствуют выбору, приглашение получено игровым клиентом. POST /instances для обычных типов обязательно проверить живым API. |
| WRITE-07 | Создать group/members, group/plus и group/public с аккаунтом с правами; повторить без прав | Правильный тип/владелец; 403 отображается, ложное «создано» отсутствует. Настройки queue/age gate в UI пока отсутствуют. |
| WRITE-08 | Пригласить согласованный тестовый контакт и запросить инвайт; выбрать два тестовых контакта для multi-invite | Доставленные уведомления у получателей; нет дубликатов, прогресс корректен. При ошибке очередь останавливается; выполнение не считается отменённым просто по закрытию диалога. |
| WRITE-09 | Принять/отклонить friendRequest, group.invite и group.joinRequest; скрыть обычное уведомление | Соответствующее серверное действие выполнено; при ошибке операция не удаляет уведомление из списка как успешно завершённое. Права группы проверить отдельно. |
| WRITE-10 | Messenger: новый текст, повтор уже сохранённого, все слоты на cooldown; ответ на invite/requestInvite | Получатель видит короткое msg-сообщение/ответ. Не редактируется cooldown-слот; совпадающий текст повторно используется. Учесть, что новый текст заменяет один из доступных шаблонов аккаунта. Проверять только согласованную отправку. |
| WRITE-11 | Вступить/выйти из тестовой группы; опубликовать тестовый пост с/без изображения и уведомления | Состояние membership и пост подтверждены другим клиентом. Без прав — ошибка. Удаление тестового поста выполнить другим клиентом, если в Mobile такого UI нет. |
| WRITE-12 | Сменить аватар через подтверждение, восстановить предыдущий | Сервер и VRChat показывают выбранный avatarId. Проверить обновление значка «Текущий» без повторного входа и после него. |
| WRITE-13 | Подписаться и отписаться от события | Реальное isFollowing и список подписок совпадают после обновления; дата и выбранный месяц не сбрасываются неожиданно. |
| WRITE-14 | Загрузить тестовый PNG/JPEG/WebP из picker, проверить обрезку и удалить загруженный файл | Предпросмотр соответствует серверному файлу; emoji подготавливается 1024×1024, прочие квадратные категории обрезаны, gallery сохраняет пропорции. Отмена picker не создаёт файл. |
| WRITE-15 | VRC+ загрузка icon/emoji/sticker, затем проверка без VRC+; переполненная коллекция | UI сообщает ограничения; серверные ошибки не выдаются за успех. Чтение существующего содержимого проверяется отдельно от права загрузки. |
| WRITE-16 | Открыть оригинал изображения и удалить только тестовый print/файл | HTTPS открывается внешним обработчиком; защищённый оригинал может потребовать отдельной браузерной сессии — это не обещание встроенного скачивания. Удаление требует подтверждения, отмена сохраняет файл. |

## Форма результата

Для каждого сценария записать: `ID`, `пройден / ошибка / не проверено`, `версия APK
и её SHA-256`, `Android/WebView/устройство`, `ориентация`, `ожидаемый и фактический
результат`. Для API-изменений указать способ независимой проверки и восстановлены
ли исходные данные. Не публиковать приватные профили или токены.

Полное соответствие ПК-версии остаётся недостигнутым даже после прохождения этого
плана: отсутствующие функции и PC companion перечислены в
[FEATURE_PARITY.md](FEATURE_PARITY.md). В план не включены как якобы готовые
SteamVR Overlay, Space Flight/Turn, PC launcher, история встреч/статистика по логам,
Voice Fight, VRCVideoCacher и другие не реализованные возможности.
