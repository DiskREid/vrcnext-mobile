# VRCNext Mobile 0.2.9 — лента аватаров и био

## Получение данных

Обычный список друзей больше не содержит точный ID аватара и био. Эти поля,
а также название, автор и изображения аватара доступны в публичном профиле
`GET /profile/{id}`. Лента теперь сравнивает обновления списка друзей и получает
публичные профили по очереди, пока приложение открыто.

Проверки ограничены одним запросом за 10 секунд для текущего аккаунта. Обычный
повтор профиля — не раньше пяти минут, сигналы WebSocket объединяются с кешем
две минуты. Для большого списка полный обход занимает больше времени. Кнопка
«Проверить профили» ставит новый обход в очередь, сохраняя ограничения запросов.

Первый снимок создаёт исходные данные, последующие сравнения фиксируют изменения.
Поэтому новая установка не получает события, случившиеся до начала наблюдения.
Био проверяется периодически: WebSocket не гарантирует передачу его изменений.
При уходе в фон или потере сети чтение останавливается; запоздалые ответы,
ответы другого аккаунта и данные, устаревшие после нового сигнала, не применяются.
401 приостанавливает запросы до ручной попытки, 429 учитывает Retry-After,
403/404 одного профиля не очищают прежние данные и не блокируют остальных друзей.

## Аватары

- Событие сохраняет доступные название, автора, ID и превью аватара.
- Если сначала пришло только новое изображение, оно отмечается как обновление
  изображения. При подтверждении публичным профилем исходная запись дополняется
  названием и точным ID, сохраняя время и ID записи без дубликата.
- Если известен прежний и новый ID, показывается «Сменил аватар». Изменение
  изображения того же ID не выдаётся за выбор другого аватара.
- Смена размера превью, CDN или query-подписи URL не создаёт событие.
  Картинка профиля и пользовательская иконка не считаются аватаром.
- Нажатие на название открывает настоящий поиск AvatarDB внутри приложения:
  результаты, следующие страницы, карточка аватара и переход к автору.
  Запрос выполняется только после нажатия, через уже существующий отдельный
  транспорт avtrdb.com. Частичная ошибка сохраняет загруженные результаты,
  429 блокирует повтор до окончания паузы.

Название берётся из возвращённых данных. Если API его не передал, оно не
выдумывается. AvatarDB может не содержать частный, удалённый или новый аватар;
совпадение названия в поиске не доказывает совпадение ID. Лента не определяет
приватность по догадке и не добавляет неподтверждённый значок замка.

## Био

Новое био видно в карточке события. В «Изменениях Bio» удалённые фрагменты
зачёркнуты красным, добавленные подчёркнуты зелёным. Сохранены Unicode, эмодзи,
переносы строк и буквальный текст, включая HTML-подобные строки. Очистка био
тоже является изменением. Сравнение вычисляется только при раскрытии карточки;
объём работы ограничен для длинного текста.

## Сохранение и проверки

Записи остаются в существующей IndexedDB по аккаунтам. Дополнение записи
сохраняется с тем же ID и переживает перезапуск; гонки чтения и записи не
возвращают старую версию. Схема базы и старые события не удаляются.
Исправлен порядок возобновления после фона, при котором новый исходный снимок
мог сразу сбрасываться другим наблюдателем.

Браузерные сценарии используют настоящий App, API-клиент, планировщик и
IndexedDB с отдельным синтетическим транспортом. Они проверяют получение
данных без открытия профиля, уточнение записи, цветной diff, поиск по нажатию,
сохранение после reload, ошибки и возврат из фона. Фикстуры не входят в APK.
Физический Tecno Spark 20 Pro / Android 13 HiOS и живой VRChat-аккаунт здесь
не проверялись. [Итоги сборки](BUILD_REPORT.md) · [Проверка на телефоне](DEVICE_TEST_PLAN.md).
