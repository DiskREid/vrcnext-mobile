# VRCNext Mobile 0.2.11 — лента по событиям

## Удаление обхода профилей

По требованию пользователя удалены добавленные в 0.2.9 периодические проверки
публичных профилей: контроллер, его таймеры/очередь, ручной запуск, прогресс
и панель. Ни запуск приложения, ни открытие/обновление ленты, ни обычное
событие статуса, входа или активности друга не запускают `/profile/{id}`.
Открытие полного профиля по-прежнему загружает его данные для отображения;
полученные реальные данные могут дополнить известный снимок без отдельного
опроса ради ленты. Сохранённые события прежних версий остаются.

## Реализация ПК-версии и мобильная обработка

Изучен `OnWsFriendUpdated` в `main/FriendsController.cs` исходного VRCNext:
поля приходят через `friend-update`, аватар сравнивается по файлу изображения,
затем точный ID/название ищется `GetAvatarIdByFileIdAsync`. Полного обхода
публичных профилей в этом обработчике нет.

Мобильная версия сразу сохраняет фактическое изменение из полученного события.
Только для уже созданной записи аватара без названия выполняется точный
`QUERY https://api.avtrdb.com/v3/avatar/resolve` с `{"file_ids":[fileId]}`.
Этот запрос получает метаданные одного изменившегося изображения, не проверяет
профиль человека. Принимается только ответ по запрошенному ключу. Био,
профиль, список друзей и произвольные URL в AvatarDB не передаются; VRChat
cookies и авторизация не попадают в отдельный клиент базы.

Название/автор/ID дополняют исходную запись с теми же ID, временем и источником.
Если точный прежний и новый ID известны, событие отмечает смену аватара.
Когда известно только изображение, это честно указано в записи. Старое превью
не используется вместо изменившегося полного изображения. Другой/более новый
аватар не получает запоздалое название предыдущего.

Кеш ограничен 100 короткими записями, одновременные запросы одного файла
объединяются. Физические запросы разделены минимум 10 секундами. Очередь
содержит только реально полученные события, максимум 100 файлов. Устаревшие
задания отбрасываются; если событий нет, нет запросов и таймера обхода.
429 учитывает Retry-After и допускает один повтор того же задания. Обычная
ошибка или отсутствие результата сохраняет изображение без выдуманного имени
и не запускает повторный опрос. Служебные hidden/loading изображения не
меняют исходный снимок и не создают ложную смену аватара при возврате к прежнему
изображению. Robot fallback не выдаётся за настоящий результат.

При уходе в фон/смене аккаунта ожидающая работа отменяется. Запоздалые ответы
не применяются; после возвращения нет обхода или воспроизведения пропущенных
событий. История остаётся в прежней IndexedDB. Фильтр ложных Trust Rank строк
из 0.2.10 сохранён без удаления исходных записей.

## Био и ограничения API

В изученной текущей ПК-версии Bio-фильтр содержит явную пометку:
“Deprecated due to VRChat API changes. Bio changes of friends can no longer
be tracked, only past entries are shown.” Старый обработчик `friend-update`
при этом всё ещё умеет сравнивать `bio`, когда это поле приходит.

Мобильная версия сохраняет изменения био только из реально полученных полей
или уже открытого полного профиля. Первое неизвестное значение создаёт исходный
снимок; отсутствие поля не означает очистку. При получении пустой строки после
известного био его очистка фиксируется. Цветное сравнение и старые записи
сохранены. Доставку всех изменений текущий VRChat API не гарантирует; скрытый
периодический опрос вместо этого не используется.

AvatarDB может не содержать файл приватного, удалённого или нового аватара.
Альтернативные базы PC (avtr.icu/vrcndb) в этой версии не добавлены. Для
неразрешённого изображения не выдумывается название/ID/приватность. Нажатие
доступного названия или ID по-прежнему открывает явный поиск AvatarDB.

## Проверки и источники

Тесты воспроизводят получение события, точное разрешение файла, сохранение
исходной записи, отсутствие сканирования за два часа простоя/после обновления
экрана, ошибки, устаревшее превью, поздние ответы, паузы и смену аккаунта.
Браузер использует настоящий App/API-клиент/IndexedDB с синтетическим транспортом;
это не результат живого VRChat-аккаунта или физического Tecno/HiOS.
