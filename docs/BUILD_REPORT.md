## Лента по событиям

Удалены планировщик обхода всех публичных профилей, ручной запуск, панель,
счётчики и автоматическое чтение `/profile/` для сбора ленты. Список друзей
только заполняет недостающие исходные данные. Фактическое изменение из WebSocket
сразу попадает в историю; точный lookup файла может дополнить ту же запись
названием/автором/ID, сохранив время, ID и источник события.

Четырнадцать тестов нового обработчика проверяют отсутствие стартовых/периодических
запросов, точный ID файла, старое превью, объединение запросов, ограниченный кеш,
свежесть результата, очередь, смену аккаунта, фон и один ограниченный повтор
после 429. Семь API-тестов проверяют точное соответствие ключа ответа и ошибки.
Два native JUnit проверяют настоящий метод QUERY, фиксированный URL, JSON payload,
отсутствие Cookie/Authorization и отклонение неверных ID.

Дополнительные тесты истории проверяют upsert исходного события, смену аватара
после получения точных метаданных, поздний ответ, несовпадающий ID, возврат из
hidden/loading изображений и сохранение самостоятельной смены явного avatarID.
Временные изображения не меняют исходный снимок и не создают две ложные записи
при возврате к прежнему настоящему изображению.

Пять сценариев ленты в двух ориентациях используют настоящий App/API-клиент/
IndexedDB с синтетическим транспортом: прямые события био/аватаров, уточнение
той же записи и поиск по нажатию, два часа простоя/обычные статусы/обновление
экрана без запросов профилей, очистка био/отсутствующее поле/перезапуск, ошибка
AvatarDB без опроса, сохранение старой истории и фильтра Trust Rank. Финальный
повтор этих десяти проверок выполнен после правок App и защиты от placeholder.
Полный132-сценарный прогон дополнительно проверяет прежние разделы и действия.
Один из них завершился ошибкой `browserContext.close: ENOENT` при сохранении
трассировки: параллельный прогон использовал ту же папку результатов. В отдельном
каталоге весь связанный набор поиска аватаров (8 тестов в двух ориентациях)
прошёл. Каталоги Playwright теперь различаются по порту, также доступен
`VRCNEXT_UI_OUTPUT_DIR`; исходный неудачный прогон не выдаётся за чистый132/132.

## Ограничения

Текущая ПК-версия VRCNext уже помечает Bio-фильтр как устаревший после изменений
API. Био фиксируется только при реально полученном поле или уже открытом полном
профиле. Доставка всех изменений не гарантируется; периодический обход для
этого не применяется. Прошлая история и цветной diff доступны.

AvatarDB может не содержать файл приватного/нового/удалённого аватара. Тогда
остаётся изображение без выдуманного имени. Метаданные запрашиваются только
для уже полученного события; альтернативные базы PC не добавлены. Пропущенные
события при остановленном приложении не восстанавливаются по догадке.
Физический Tecno Spark20Pro/Android13 HiOS, живой VRChat-аккаунт и выполнение
Android instrumentation этой версией здесь не проверялись.

`releases/v0.2.11`: APK, исходникиZIP, SHA256SUMS, validation.json и снимки
синтетической ленты. Исходники сверены с коммитом, исключают ключи, SDK/JDK,

настоящий GitHub Release и сверяет размеры/SHA256 вложений. Старые версии
не заменяются.
