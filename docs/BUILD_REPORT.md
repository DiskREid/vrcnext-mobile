## Исправление причины пропуска событий

ПК-обработчик `friend-update` и его цепочка разрешения файла изучены на текущем
remote main `0bfb467f89caa21893769f6495abe334febe08a3`.
Вместо сравнения одинаковых старых полей используются единый ID файла и
современный `iconUrl` с подтверждением того, что файл относится к аватару.
Переход между full/thumbnail больше не теряется; версии одного файла не
создают смену. Состояние connecting и ошибка наблюдения своего location
останавливают посещения, сохраняя исходный снимок ленты.

51 тест истории проверяет прежние функции и новые регрессии: современные
кандидаты, обе стороны, название без ID, переходы между полями, восстановление
снимка после status-only события/паузы, игровые паузы и историческую привязку.
Кандидаты иконок не попадают в публичную историю и IndexedDB до подтверждения.
Переход A → пользовательское фото → B не отображает фото как старый аватар:
эта сторона остаётся неизвестной до точного подтверждения прежнего файла.

20 тестов обработчика метаданных проверяют обе стороны и привязку к событию,
быстрые A → B → C, кеш, объединение запросов, интервал1с, ошибки429, паузы,
смену аккаунта, ограниченные данные и отсутствие запросов при простое.
11 API-проверок подтверждают AvatarDB → ICU → официальный файл, точное
соответствие ключей, имя без выдуманного avatar ID, ошибки и исключение
пользовательских иконок. Четыре native теста конструктора запросов проверяют
точные QUERY/URL/JSON обоих сервисов, перечисление источников, отсутствие
Cookie/Authorization и отклонение неверных ID. Полный нативный набор —36.

## Интерфейс и сохранение

Десять сценариев ленты в двух ориентациях используют настоящий App/API-клиент/
IndexedDB с синтетическим транспортом. Они проверяют современные события,
оба кликабельных имени/превью, сохранение одного ID/времени записи, резервные
источники, обычное фото и возврат к аватару, подключение после загрузки друзей,
два часа простоя без обхода профилей, старую историю/Trust Rank и события Bio.
Снимки используют синтетические изображения; они не являются данными живого
аккаунта и не входят в APK. Полный142-сценарный прогон также проверяет прежние
разделы: инвайты, избранное, группы, граф/реальные касания, присутствие,
уведомления, медиатеку, календарь и навигацию. Каталоги результатов разделены
по порту, что исключает конфликт трассировок параллельных прогонов.

Реальный `QUERY /v3/avatar/resolve` вернул HTTP200 и точный ключ файла
`file_73bdcab2-a4f6-4652-a13a-45202d4c210d`, avatar ID
`avtr_5fd7f38a-c3d4-4f41-aada-8cc20a9633e3`, название `VRoomba-gen`.
Использован публичный файл, без VRChat cookies и авторизации. Это подтверждает
контракт первого сервиса, а не смену аватара живого друга.

Живые запросы ICU/авторизованного `/file/`, физический Tecno Spark20Pro/Android13
HiOS, живой VRChat-аккаунт и Android instrumentation здесь не проверялись.
Если VRChat не передал изображение/ID или источники не раскрывают файл,
название/ID не выдумываются. Подписанная vrcndb с приватными ключами не
перенесена. Био не опрашивается: текущий ПК также помечает этот фильтр
устаревшим из-за изменений API. История между остановками приложения не
восстанавливается по догадке.
